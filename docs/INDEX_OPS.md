# 인덱스 운영 — /admin 으로 하는 일

검색 인덱스를 확인하고, 사전을 갱신하고, 문제가 생기면 되돌리는 방법입니다. 전부 브라우저나
`curl`로 되며, PC에서 CLI를 돌리거나 Render 환경변수를 고칠 필요가 없습니다.

> 기준: 2026-09-28 master. 출처: `src/notice_ai/`의 api.py · index_ref.py · dictionary.py · index_setup.py

## 먼저 알아야 할 것 — 별칭

코인 한글명 사전(Nori `user_dictionary_rules`)은 **인덱스 설정에 박히고, 분석기는 색인 시점에
적용됩니다.** 그래서 새 코인이 상장되면 그 이름은 사전에 없는 채로 쪼개져 색인되고
(`네이로` → `네이` + `로`), 그 이름으로는 검색이 안 됩니다. 고치려면 인덱스를 새로 만들어
문서를 옮기는 수밖에 없습니다.

인덱스 이름을 환경변수가 직접 가리키면, 옮길 때마다 Render 대시보드에서 `NOTICE_INDEX`를
손으로 고쳐야 합니다. 그 한 걸음이 사람 손이라 나머지를 자동화해도 이어지지 않습니다.

그래서 **별칭**을 둡니다.

```
notices_live  ──▶  notices_20260928120000     ← 검색·색인은 왼쪽만 본다
    (별칭)              (진짜 인덱스)
```

새 인덱스로 옮길 때 별칭만 돌리면 되고, 그 전환은 OpenSearch에서 원자적이라 검색이 한 건도
안 끊깁니다. 옮기다 실패하면 별칭이 그대로 옛 인덱스를 가리키므로 저절로 복구됩니다.

| 환경변수 | 기본값 | 뜻 |
|---|---|---|
| `NOTICE_ALIAS` | `notices_live` | 검색·색인이 보는 별칭. 비우면 별칭 없이 돈다 |
| `NOTICE_INDEX` | `notices_v3` | 별칭이 없을 때 쓰는 이름이자, 새 인덱스 이름의 앞머리 |
| `DICT_AUTO_REBUILD` | `1` | 0이면 감지만 하고 재색인은 안 한다 |
| `DICT_REBUILD_MIN_SEC` | `21600` | 재색인 최소 간격(6시간) |

## 처음 한 번: 별칭 만들기

**별칭이 없으면 자동 갱신이 돌지 않습니다.** 감지는 되지만 전환에서 멈춥니다. 배포 후 한 번만
해 주면 됩니다.

브라우저 주소창에 붙여넣습니다.

```
https://<서버주소>/admin/dictionary/alias?token=<토큰>
```

`index`를 안 주면 지금 `NOTICE_INDEX`를 가리킵니다. 다른 인덱스를 지정하려면:

```
https://<서버주소>/admin/dictionary/alias?index=notices_v4&token=<토큰>
```

응답:

```json
{"alias": "notices_live", "before": [], "now": "notices_v4"}
```

확인은 `/health?deep=1` 로 합니다.

```json
"opensearch": {"index": "notices_live", "points_at": "notices_v4", "docs": 1234}
```

`index`가 별칭이고 `points_at`이 실제 인덱스면 된 것입니다. `docs` 건수가 전과 같은지도 봅니다.

> 여러 번 눌러도 안전합니다. 같은 인덱스를 다시 가리킬 뿐이고 데이터를 만들지도 지우지도
> 않습니다. 그래서 이것만 GET으로 열어 두었습니다.

## 엔드포인트 넷

모두 `?token=<토큰>`이 필요합니다.

| 엔드포인트 | 메서드 | 하는 일 | 무겁나 |
|---|---|---|---|
| `/admin/dictionary/status` | GET | 자동 갱신 상태 | 검색 서버를 안 부른다. 즉시 |
| `/admin/user-dictionary` | GET | 코인명이 쪼개지는지 진단 | `_analyze` 몇 번. 수 초 |
| `/admin/dictionary/alias` | GET·POST | 별칭 만들기·돌리기 | 즉시 |
| `/admin/dictionary/rebuild` | **POST만** | 새 인덱스로 옮기고 전환 | 문서 수에 따라 수 분 |

`rebuild`만 POST인 이유: 인덱스를 새로 만들고 문서를 통째로 복사하므로, 주소가 어딘가
남아 잘못 눌리면 안 됩니다.

```bash
curl -X POST "https://<서버주소>/admin/dictionary/rebuild?token=<토큰>"
```

> `?token=`을 붙인 POST는 리다이렉트 없이 바로 실행됩니다. 전에는 303 리다이렉트가 POST를
> GET으로 바꿔 조용히 아무 일도 안 일어났습니다(GOTCHAS 참고).

## 평소에 보는 법

```
https://<서버주소>/admin/dictionary/status?token=<토큰>
```

```json
{
  "auto": true,              // 자동 갱신 켜짐
  "min_sec": 21600,
  "running": false,          // 지금 재색인이 도는 중인지
  "stale": [],               // 사전에 없어 검색이 안 되는 이름
  "stale_since": "",
  "last_checked": "2026-09-28 14:03:11",
  "last_rebuild": null,
  "alias": "notices_live"
}
```

**`stale`이 비어 있으면 사전이 코인 목록을 따라잡은 것입니다.** 평소에는 이것만 보면 됩니다.

뭔가 남아 있는데 `last_rebuild`가 실패로 끝나 있으면, 그 `message`가 이유입니다.

| `reason` | 뜻 | 할 일 |
|---|---|---|
| `count_mismatch` | 옮긴 건수가 원본과 다름 | 다음에 다시 돈다. 수집 중이었을 가능성 |
| `reindex_failures` | 옮기다 실패한 문서 있음 | `dest` 인덱스를 보고 원인 확인 |
| `empty_dictionary` | 사전이 비어 있음 | 빗썸 호출이 되는지 확인 |
| `coins_failed` | 빗썸 목록을 못 받음 | 네트워크·빗썸 상태 |
| `already_running` | 이미 도는 중 | 기다린다 |

어느 경우든 **별칭은 그대로**라 검색은 계속 됩니다.

## 사전이 뒤처졌을 때

보통은 아무것도 안 해도 됩니다. 10분마다 도는 빗썸 갱신이 신규 상장을 감지하면 알아서
재색인합니다.

지금 당장 돌리고 싶을 때(자동이 꺼져 있거나, 최소 간격을 기다리기 싫을 때):

```bash
curl -X POST "https://<서버주소>/admin/dictionary/rebuild?token=<토큰>"
```

돌아가는 순서:

```
빗썸 목록 받기 → 사전 만들기 → 새 인덱스 생성 → 문서 복사 → 건수 확인 → 별칭 전환
```

어디서 멈춰도 별칭은 옛 인덱스를 가리킨 채입니다. **실패가 곧 복구입니다.**

응답이 끊겨도 서버에서는 계속 돕니다. 결과는 `status`의 `last_rebuild`로 봅니다.

효과를 숫자로 보려면 재색인 전후에 진단을 찍어 둡니다.

```
https://<서버주소>/admin/user-dictionary?token=<토큰>
```

`missing`이 0이면 지금 인덱스가 모든 코인명을 통째로 잡는다는 뜻입니다. 재색인 직후에는
0이어야 합니다.

## 되돌리기

**별칭을 옛 인덱스로 돌리면 즉시 복구됩니다.** 환경변수를 고칠 필요가 없습니다.

```
https://<서버주소>/admin/dictionary/alias?index=notices_v4&token=<토큰>
```

어느 인덱스가 있는지는 `status`의 `last_rebuild.source` / `.dest`, 또는 `/health?deep=1`의
`points_at`으로 찾습니다. 이름에 시각이 붙어 있어 사전순이 곧 시간순입니다.

별칭 자체를 안 쓰려면 Render에서 `NOTICE_ALIAS`를 **빈 값**으로 둡니다. 그러면 `NOTICE_INDEX`를
직접 보는 예전 방식으로 돌아갑니다.

---

## 옛 인덱스 정리

재색인할 때마다 인덱스가 하나씩 쌓이고, **자동으로 지우지 않습니다.** 되돌릴 곳이 남아 있어야
하기 때문입니다.

지우는 엔드포인트는 일부러 만들지 않았습니다. 인덱스 삭제는 되돌릴 수 없는데 공유 토큰 하나로
열어 두기엔 위험합니다(#6에서 다룰 부분). 가끔 OpenSearch 대시보드나 PC에서 직접 지웁니다.

지울 때 기준:
- 지금 별칭이 가리키는 것은 **절대 지우지 않습니다**(`/health?deep=1`의 `points_at`)
- 바로 앞 것 하나는 되돌릴 곳으로 남겨 둡니다
- `notices_v3`·`notices_v4` 같은 옛 이름도 한동안 두는 편이 낫습니다

## 자동 갱신을 끄고 싶을 때

Render Environment 탭에서:

| 하고 싶은 것 | 설정 |
|---|---|
| 감지만 하고 재색인은 수동으로 | `DICT_AUTO_REBUILD=0` |
| 더 자주 돌게 | `DICT_REBUILD_MIN_SEC`를 낮춘다 |
| 별칭 자체를 안 씀 | `NOTICE_ALIAS`를 빈 값으로 |

`DICT_AUTO_REBUILD`는 호출할 때마다 환경변수를 다시 읽으므로 **재시작 없이** 꺼집니다.

## CLI로 하는 같은 일

사내망이나 PC에서 직접 돌릴 때. `.env`가 같은 OpenSearch를 가리켜야 합니다.

```bash
py -m notice_ai.cli alias --index notices_v4   # 별칭 만들기·돌리기
py -m notice_ai.cli rebuild-dict               # 사전 갱신 → 새 인덱스 → 전환
py -m notice_ai.cli check-dict                 # 진단(색인 안 건드림)
```

**`setup-index`를 직접 쓸 때 주의**: 코인 목록은 프로세스 메모리 캐시라 CLI에서는 비어 있습니다.
지금은 `setup-index`가 먼저 빗썸에서 받아 오고 사전 개수를 찍습니다. 그 숫자가 두 자리로 나오면
목록을 못 받은 것이니 거기서 멈추고 다시 실행합니다. 사전이 거의 없는 인덱스가 만들어집니다.

## 알아 둘 제약

**Render 프리 티어는 15분 놀면 잠듭니다.** 자는 동안은 갱신 루프가 안 돌아 감지도 쉽니다.
깨어나면 따라잡습니다 — 검색을 쓰는 시점에는 최신이라 실용적으로는 괜찮지만, 내부망 서버로
옮기면 이 제약이 없어집니다.

**재색인 도중에 들어온 공지는 새 인덱스에 없습니다.** `reindex`는 시작 시점의 문서만 옮깁니다.
그래서 전환 전에 건수를 비교해 다르면 멈춥니다. 수집과 재색인이 겹치면 `count_mismatch`로
끝나는데, 실패가 아니라 **의도된 안전장치**입니다. 다음 기회에 다시 돕니다.

**`/admin/*`는 공유 토큰 하나로 열립니다.** 이제 인덱스를 만들고 별칭을 돌리는 엔드포인트라
권한이 전보다 셉니다. 역할을 나누는 것은 #6(접근 통제)에서 다룹니다.

**사전에는 상한이 있습니다.** `MAX_DICT_WORDS = 3000`. 설정에 직접 넣는 배열이라 무한정 늘릴 수
없습니다. 넘으면 잘라 내고 경고만 남기므로, 코인이 그만큼 늘면 다시 봐야 합니다.
